The Testosteronium Ecosystem operates on a Server-Agent architecture.Testosteronium Admin Console (Server UI): Used strictly by IT Administrators to monitor assets, control security policies, review network-discovered devices, and deploy management patches.Testosteronium User Console (Client Agent): A lightweight background service installed on company PCs/laptops. It automatically gathers inventory metrics, prevents unauthorized uninstallation via OTP verification, and communicates securely back to the Admin Console via REST APIs and WebSockets.1. 1. Tracked Assets (Automated Agent)Mechanism: Populated automatically when the Testosteronium User Console agent is installed on an end-user device.Security & Tamper Protection:The Agent runs as a protected System Service.OTP Uninstall Protocol: If an end-user attempts to uninstall or modify the User Console, the local uninstaller prompts for an Administrator OTP. The user must request this dynamic code from the Admin Console. Without a valid OTP generated by an admin, uninstallation fails.Data Collected: Hardware specs (CPU, RAM, Storage), OS version, installed software, logged-in user, running processes, and public/local IP addresses.2. Manual AssetsMechanism: Designed for devices that cannot run the User Console (e.g., legacy machines, network printers, unmanaged hardware).Entry Points:Single entry via Add Asset modal.Bulk entry via Import from Excel / CSV.3. Fetching / Network Discovered AssetsMechanism: When an end-user device connects to the company local network, VPN, or a designated company PC hotspot, the network discovery module detects the active IP/MAC address.Action: Discovered network devices appear in an "Uncategorized Network Assets" queue in the Admin Console, allowing admins to instantly convert them to tracked or manual records with one click.3. Core Features of the Management CardA. Manual-to-Tracked Conversion PipelineWhen an asset is manually added (via Excel or form) and later connects to the network or installs the User Console, the Management module maps the manual record to the live agent telemetry using MAC/Serial Number verification.B. Patch & Configuration DeploymentAdmins can build and schedule update packages or system configuration files (e.g., registry edits, firewall rules, script execution) directly from this view.C. Policy Distribution EngineDefine security rules centrally in the Management tab (e.g., block specific USB storage devices, restrict network adapters, enforce background ping rates) and broadcast them down to target User Consoles.D. Enforcement Logs & Audit TrailEvery deployment action maintains an immutable execution log detailing:Target Node IDDeployment TimestampExecution Status (SUCCESS, PENDING, FAILED)Error Log Output (if script execution fails)
